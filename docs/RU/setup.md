# Создание проекта из шаблона Dejavue (cruft)

Dejavue — cookiecutter-шаблон монолитного приложения на Django + Inertia +
Vue/React. Для создания проекта из шаблона и последующего обновления
рекомендуется использовать [cruft](https://github.com/cruft/cruft).

## Требования

- Python 3.14+
- Node.js 22+
- Docker (для продакшена)
- `cruft` (ставится через `pipx` или `uv tool`)

## Установка cruft

```sh
pipx install cruft
```

или через `uv`:

```sh
uv tool install cruft
```

Проверьте установку:

```sh
cruft --version
```

## Создание проекта

Создайте новый проект из шаблона:

```sh
cruft create https://github.com/netstuff/dejavue
```

cruft задаст вопросы из `cookiecutter.json`:

| Параметр          | Описание                                          |
|-------------------|---------------------------------------------------|
| `project_name`    | Название проекта                                  |
| `description`     | Краткое описание проекта                          |
| `domain_name`     | Домен (используется для генерации email автора)   |
| `author_name`     | Имя автора                                        |
| `version`         | Версия проекта                                    |
| `timezone`        | Часовой пояс, например `UTC` или `Europe/Moscow`  |
| `language`        | Локаль, например `ru-RU`                          |
| `frontend`        | Фронтенд: `none`, `vue`, `react`                  |
| `docker_registry` | Реестр Docker, куда отгружаются готовые образы    |

⚠️ Используйте `frontend:none` если у вас уже есть в наличии фронтенд. Вам будет предложено подгрузить его в проект.

После ответов на вопросы cruft:

1. сгенерирует проект в директории `{{ cookiecutter.project_slug }}`;
2. создаст в корне проекта файл `.cruft.json` — «связь» проекта с шаблоном,
   которая понадобится для обновлений;
3. выполнит post-generation hook, который установит npm-зависимости.

Также можно указать директорию вывода и имя проекта без интерактивного режима:

```sh
cruft create https://github.com/netstuff/dejavue \
  --output-dir ./ \
  --no-input \
  --config-file /path/to/cookiecutter.json
```

## Первый запуск проекта

Перейдите в созданный проект и выполните установку:

```sh
cd <project_slug>
make install
```

Запустите проект в режиме разработки:

```sh
make dev
```

Приложение будет доступно по адресу `http://localhost:8000` (фронтенд dev-сервер
Vite — на `:5173`).

Полезные команды:

```sh
make dev          # бэкенд (:8000) + фронтенд (:5173)
make build        # production-сборка
make test         # тесты (pytest)
make lint         # линтинг (ruff + mypy)
```

Инструкция по развертыванию в продакшене — в файле
[docs/RU/deployment.md](deployment.md).

## Обновление проекта из шаблона (cruft)

### Как работает связь с шаблоном

При создании проекта cruft записывает в `.cruft.json` ссылку на шаблон и коммит,
из которого проект был создан. Обновление — это перенос изменений шаблона в ваш
проект относительно этой записи.

### Проверка наличия обновлений

```sh
cruft check
```

Команда возвращает ненулевой код, если в шаблоне появились новые изменения.
Полезно для CI: например, `cruft check` в пайплайне предупредит об отставании
проекта от шаблона.

### Применение обновлений

```sh
cruft update
```

Эта команда:

1. скачает последние изменения шаблона;
2. применит их к файлам проекта;
3. обновит `commit` в `.cruft.json`.

### Обновление «в сухую» и просмотр diff

Чтобы сначала посмотреть изменения, не применяя их:

```sh
cruft update --skip-apply
cruft diff
```

`cruft diff` показывает разницу между текущими файлами проекта и тем, что cruft
хочет применить. После просмотра примените изменения:

```sh
cruft apply
```

### Возможные конфликты

Если вы меняли файлы, которые управляются шаблоном, cruft попытается выполнить
трёхстороннее слияние. При конфликте cruft оставит оба варианта в файле, а в
`.cruft.json` не обновит коммит. Разрешите конфликты вручную, затем обновите
`.cruft.json`:

```sh
cruft update --skip-apply
# разрешить конфликты в файлах
cruft apply
```

### Обновление до конкретной версии шаблона

Можно подтянуть изменения из конкретного тега или ветки:

```sh
cruft update --checkout v0.2.0
cruft update --checkout main
```

### Связывание существующего проекта

Если проект уже существует и в нём нет `.cruft.json`, его можно «привязать» к
шаблону:

```sh
cruft link https://github.com/netstuff/dejavue
```

### Обновления и деплой

После `cruft update` обязательно проверьте, не затронуло ли обновление
деплой-конфигурацию (`Dockerfile`, `deploy/`, `skills/deployment/`), пересоберите
образ и перезапустите контейнер — см.
[docs/RU/deployment.md](deployment.md).
